## 1. PROJECT OVERVIEW

- Zentra = Student Information & Management System for **Mati School of Arts and Trades**, Grades 7–12, **trimester** (3 terms per school year).
- 11 roles (Prisma `Role`): student, parent, subject_teacher, adviser, nurse, adm_coordinator, guidance_counselor, record_keeper (band G7–10), registrar (band G11–12), principal, admin (system administrator — dedicated `/login/admin` portal, lands on `/admin/overview`; never accepted by the staff portal).
- 8 staff web shells exist; **student/parent can log in but have no desk** (login fallback routes 404 — see Gotchas).
- Features: grading workspace + DepEd transmutation + finals lock/approve; attendance (legacy AM/PM + per-subject) with auto-absent sweep; anecdotal records (GCForm‑01) + folders/signatures; referral pipeline (triage → counseling/nurse sessions → interventions) and ADM case flow (profile → meetings → certification → principal sign → modules/devices → completion); SF10 records (upload/OCR, versions, verify→validate→release); rule-based risk engine; dashboards/heatmaps/reports/honor-roll/audit; notifications fan-out; per-role realtime; print record sheets.

Clinic (nurse) desk actions on the same ADM track ring a second set of adviser-only clips — `/sounds/nurse_adm_booked_session.mp3` (`isAdviserAdmBookedClinic`), `/sounds/nurse_adm_reschedule.mp3` (`isAdviserAdmRescheduledClinic`), `/sounds/nurse_create_referral.mp3` (`isAdviserAdmEndorsedClinic`) and `/sounds/nurse_adm_reject.mp3` (`isAdviserAdmRejectedClinic`) — dispatched on the same `ADVISER_ADM_*`/`ADVISER_REFERRAL_UPDATE_EVENT` events with a `clinic` detail flag, catch-up included; the nurse desk itself stays silent. The clinic classifiers run first (every clinic row also matches its guidance counterpart) and key off the nurse fanout wording: `(Clinic) booked an ADM consultation session`, `Clinic rescheduled an ADM consultation session`, `(Clinic) endorsed the ADM consultation`, `not endorsed by the clinic`. Rejecting also stays silent instead of the generic cancelled-referral clip, `/sounds/cancelled referral.mp3` when the filing teacher withdraws one (`isReferralCancelled`), `/sounds/risk alert.mp3` only when the guidance **interventions** desk data changes (never for alerts/referral/anecdote housekeeping), and `/sounds/ADVISER RISK ALERT.mp3` in the teacher shell when one of the adviser's own advisees newly appears in intervention detection (the adviser's own `/teacher/advisory/interventions` board polled from `app/teacher/components/AdviserRiskAlertMonitor.tsx`, diffed the same way the guidance shell diffs its board — the risk engine only notifies on a *new* factor, so a live-recomputed detection with no plan emits nothing and the board poll is what makes it ring off-page and on other sites; a learner rings **once** per detection and stays silent for later card/plan/session/outcome updates, including the `intervention_detected` fanout that fires when guidance opens the intervention, and re-arms only if they leave detection and return — the alerted set resets per term). `/sounds/intervention session alert booked.mp3` (`adviserSession`) rings in the teacher shell when guidance books an intervention session for one of the adviser's own advisees: `teacherChannel`'s notification handler matches `isAdviserSessionBooked` (type `intervention_session` + "booked an intervention session"/"opened a follow-up" text — plan reviews, assignments and completions share that type and stay silent — moves and cancellations have their own clips) and dispatches `ADVISER_SESSION_ALERT_EVENT`, which the same monitor plays; a booking that landed while the adviser was signed out rings once on login through `useDeskCatchUp` (`role: "adviser"`, `clipFor` = the same classifier). `/sounds/intervention resched.mp3` (`adviserSessionResched`) is the same wiring for "Guidance rescheduled an intervention session …" (`isAdviserSessionRescheduled` → `ADVISER_SESSION_RESCHED_EVENT`, catch-up included). `/sounds/intervention cancelled.mp3` (`adviserSessionCancelled`) is the same wiring for "Guidance cancelled an intervention session …" (`isAdviserSessionCancelled` → `ADVISER_SESSION_CANCELLED_EVENT`, catch-up included); the realtime `CounselingSession` UPDATE to `cancelled` fires the same event, so a dropped slot never sounds like a booking. The adviser desk also mirrors the **referral** pipeline it filed: `/sounds/guidance create referral.mp3` (`adviserReferralUpdate`, via `isAdviserReferralEndorsed` → `ADVISER_REFERRAL_UPDATE_EVENT`) when guidance endorses the ADM consultation (adviser-only; the guidance desk stays silent) and `/sounds/cancelled referral.mp3` (`adviserReferralClosed`) when it rejects/dismisses/closes the case (`isAdviserReferralClosed` → `ADVISER_REFERRAL_CLOSED_EVENT`); clinic/counseling session messages on that referral ("booked/rescheduled/cancelled a session for …") ring the same adviser session clips, notification-driven because RLS publishes only *intervention* sessions to the adviser. A registry desk (record keeper G7–10 / registrar G11–12) **granting** the SF10 access an adviser requested rings `/sounds/record keeper granted request.mp3` (`adviserSf10Granted`) on that adviser's desk — `isAdviserSf10Granted` matches only approved wording on the `adviser_sf10_access_requests` fanout (whole-request, per-LRN and approve-all paths), denials and the desk's own "You granted …" row stay silent; the registrar's grant rings its own `/sounds/registrar granted access.mp3` (`adviserSf10GrantedRegistrar`, matched by the `granted by the registrar desk` wording the backend adds to the grant message), checked first because it also matches the generic classifier; the access-request table is not published over realtime, so the notification is both the live and the login-catch-up path (`clipFor` in the adviser monitor); a learner the desk could not match rings its own `/sounds/record keeper missing sf10.mp3` (`adviserSf10Missing`, `isAdviserSf10Missing` matches the `report-missing` fanout "No SF10 on file for …"), and the registrar's missing report rings `/sounds/registrar missing sf10.mp3` (`adviserSf10MissingRegistrar`, matched by `reported missing by the registrar desk`), same live + catch-up path. The mirror exchange belongs to the registry desks: an adviser filing an SF10 access request rings `/sounds/teacher access request sf10.mp3` (`registrySf10Request`, matched by `isSf10AccessRequested` on the `create` role-fanout wording "SF10 access requested: …"; the adviser's own "Your SF10 access request …" echo stays silent) on the record keeper / registrar desk — `recordKeeperChannel.ts` and `registrarChannel.ts` prime that one clip, ring it live (realtime insert + 5s poll fallback) and again on login catch-up (`role: "record_keeper"` / `"registrar"`); the adviser's own desk never loads it. One clip plays at a time (`isDeskSoundPlaying` bus); `primeDeskSounds([...])` preloads only the clips that desk owns (guidance: referral/cancelled/risk — the four ADM confirmation clips are adviser-only; teacher: `adviserRisk` + `adviserSession` + `adviserSessionResched` + `adviserSessionCancelled` + `adviserReferralUpdate` + `adviserReferralClosed` + `adviserAdmRejected` + `adviserAdmBooked` + `adviserAdmRescheduled` + `adviserAdmRejectedClinic` + `adviserAdmBookedClinic` + `adviserAdmRescheduledClinic` + `adviserAdmEndorsedClinic` + `adviserSf10Granted` + `adviserSf10Missing` + `adviserSf10GrantedRegistrar` + `adviserSf10MissingRegistrar`; nurse/coordinator/principal: referral/cancelled; record keeper/registrar: `registrySf10Request`) and the first gesture unlocks them, and `playDeskSound` refuses any kind the page did not prime. The actor's own desk never rings its own action (self-notification suppression). Login catch-up lives in `frontend/src/lib/notify/deskCatchUp.ts` (`useDeskCatchUp`): on the first mount of a desk for a user it reads that user's **unread** desk notifications (`/api/notifications/?take=50&unreadOnly=1`), keeps the ones newer than the stored `zentra.desk.seen.<role>.<userId>` stamp (a browser that never opened the desk has no stamp, so everything waiting counts), then rings the matching clip once (deferred to the first click/keypress when audio is still locked, via `hasDeskSoundGesture`/`ringCatchUp`) plus one "N updates waiting" toast, throttled to one catch-up ring per desk per 5 min (`zentra.desk.rangAt.*`). The guidance monitor never rings for a card that is merely sitting on the board or for a login catch-up, and its gesture unlock probe is muted so the first click never leaks the clip. The risk clip rings from the `intervention_detected` realtime notification the moment it lands (the same shape as a referral arrival), with the interventions-board diff as the fallback for a detection that emits no notification. Either way a learner rings **once** when they enter detection and stays silent while they remain at risk no matter how their card/plan/session/outcome updates; a learner who drops out of High/Moderate (including a recovered "Low + ongoing" card that stays on the board) re-arms, so a relapse rings again. The guidance desk's "already rung" set is persisted per user + school year (`zentra.guidance.risk.rung.*`) exactly like the adviser's, so the first visit seeds silently but a reload/re-login does not swallow a learner detected just before the desk was opened. A ring only counts as delivered when playback actually started, so a clip throttled mid-burst is retried on the next poll instead of muting the learner for the term. Realtime `Intervention`/`CounselingSession`/`RiskSnapshot` frames and the nav-counts diff only refetch the board, so none of them can re-ring an already-alerted learner. The adviser monitor's "already rung" set persists per adviser + term in `localStorage` (`zentra.adviser.risk.rung.*`), so a reload replays nothing but an advisee detected while the adviser was signed out rings once on arrival (the very first visit seeds silently); a learner already rung is never re-rung for later card/plan/session/outcome updates, and only leaving detection re-arms them. Wired in the adviser monitor and the nurse / coordinator / principal channels; the nurse channel additionally rings `/sounds/referrals.mp3` straight off the `Referral` row (RLS only publishes referrals addressed to the nurse, picked as its consult reviewer, filed by them or advised by them; the row's own `referredBy` is skipped), and rings `/sounds/cancelled referral.mp3` off that same row when the filing teacher withdraws a clinic case (`status` → `dismissed`, once per dismissal, suppressed when the nurse dismissed it themselves), so a case that lands on or is re-routed to / withdrawn from the clinic never depends on the fanout notification — `consultReviewer` stores the reviewer **role** (`"nurse"`), so `referral_visible` matches it against `zentra_role()` (it used to compare to `zentra_uid()`, which is why an ADM case out for nurse consultation never arrived on the nurse desk live). A clip requested before the page has seen its first gesture is parked by `playDeskSound` and rung on that gesture (90s max) instead of being dropped by the autoplay policy.
- **Realtime**: Supabase `postgres_changes` channels per role — `frontend/src/lib/realtime/*Channel.ts` (all 8 shells wired). Published tables: `Notification`, `Referral`, the `Adm*` set, `Section`, `Intervention`, `CounselingSession`, `RiskSnapshot`. The realtime token (`GET /api/auth/realtime-token`) keeps `role: "authenticated"` for Supabase and carries the Zentra role in an `app_role` claim that `zentra_role()` prefers — RLS policies on those tables key off it. `0001_rls.sql` also grants `authenticated` schema USAGE + SELECT on exactly those published tables (this DB has no default grants), otherwise Realtime silently delivers nothing. Never bind a `postgres_changes` subscription with a filter on a camelCase column (`filter: userId=eq.…`): Realtime lowercases the identifier, rejects the binding, and that takes the whole channel's CDC stream down — the `Notification` streams are RLS-scoped `notification_own` instead, and each channel drops other users' rows in code.

## 3. ARCHITECTURE

- Two apps: `backend/` REST API under `/api/*`; `frontend/` Next App Router with one route tree + layout per role shell.
- Backend layering: `modules/<domain>/*.routes.ts` (thin handlers, Zod via `validate` middleware) → `*.repository.ts` / `services/<domain>.ts` (domain logic) → Prisma. Shared kernel in `backend/src/lib/`.
- Auth: JWT access (localStorage `zentra.access`) + refresh in httpOnly cookie; 401 → single-flight refresh → retry → `/errors/403` (`frontend/src/lib/api/client.ts`). Claims: `sub`, `role`, `gradeBand`. Guards: `requireAuth`, `requireRole`, `requireOwnershipOrRole` (`backend/src/middleware/auth.ts`), `gradeBandGuard` (`middleware/gradeBand.ts`).
- Term scoping (`backend/src/lib/termScope.ts`, mounted via `app.ts` → `attachTermScope`): only **term-steering roles** (subject_teacher, adviser, principal, admin — `canSteerTerm` in `backend/src/lib/roles.ts`) may steer term via `?termId`/`?schoolYearId` or `x-term-id`/`x-school-year-id`; every other role resolves server-side (active school year → date-picked term). The principal picks one scope in `/principal/settings` (stored per user in localStorage, like teachers) and every principal page follows it. Exception: `GET /api/reports` (principal) accepts explicit `termId`/`schoolYearId` query params for the reports scope picker — they default to the server-resolved active scope and are looked up/validated by the service. Resolution is memoized in-process for 30s (`active`, `term:<id>`, `year:<id>`, single-flight) because it runs on every `/api` request — one pooler round trip per request otherwise; any path that creates/activates a term or school year must call `invalidateTermScopeCache()` (`academics-catalog.routes.ts`, `registry.repository.ts`, `academics.sections.service.ts` today).
- Caching: Upstash Redis GET-cache keyed method+path+qs+role+user+term-scope, tag invalidation (`lib/cache.ts`, `lib/cacheTags.ts`); TTLs dashboard 15s / list 30s / semiStatic 300s / lookup 3600s; ETag middleware; `ReportSnapshot` DB fallback for reports. Redis absent → fail-open, caching off. **Every Redis call is raced against a hard timeout** (`redisOp` in `lib/redis.ts`, 1.2s read / 3s write): a rejected token or an Upstash outage used to add 6–20s to every cached route because the client retries and each PH→Upstash round trip is ~1s. Any new Redis call site must go through `redisOp`. A GET carrying `x-zentra-fresh: 1` skips the cache **read** (the fresh body still overwrites the entry) — the API client sets it for 10s after any realtime invalidation (`lib/api/fresh.ts`), so a board refetching off a notification can't race the write's fire-and-forget tag invalidation and render the pre-write payload.
- Pagination: **15/page, max 15, everywhere** — two exceptions, both guidance-desk boards that lay out a 4×4 card grid: the referrals queues (nurse kanban boards — ADM cases + Clinic matters — and guidance queues) accept up to **16/page** (`NURSE_QUEUE_MAX_PAGE_SIZE` in `modules/referrals/referrals.schemas.ts`), and the guidance interventions queue does too (`INTERVENTIONS_QUEUE_MAX_PAGE_SIZE` in `modules/interventions/interventions.schemas.ts`); the global ceiling in `lib/pagination.ts` is unchanged. Desk services that merge several sources into one board (guidance alerts desk → `/api/guidance/alerts/cases`) load each source up to the internal-only `INTERNAL_AGGREGATE_ROW_CAP` (400) and page the merged list themselves — never wired to a client query param. Envelope `{data,total,page,pageSize,totalPages}`; frontend shared `Pagination` + `usePaginatedQuery` (`keepPreviousData` + next-page prefetch + AbortSignal).
- Writes: `writeAudit` (`lib/audit.ts`; pass the tx client inside `prisma.$transaction` or it fails loudly), `fanoutNotification` (`lib/notify.ts`, `source_table:action` → type map), `invalidateTags([...])`, live risk recompute.
- Background sweeps from `backend/src/index.ts` hourly: grade-flag escalation, auto-absent, risk snapshots.
- Frontend data flow: page → `services/<role>/*.service.ts` hook (TanStack Query, canonical `queryKey`/`CACHE_PRESETS`) → `apiClient` (+term headers for teachers) → API. Lists use URL-synced page/filters.
- Teacher shell is **live**: everything reachable from `app/teacher/**` (subject teacher + adviser) uses `useLiveQuery`/`useLiveQueries` from `frontend/src/lib/api/live.ts` or passes `liveQueryOptions` to `usePaginatedQuery`, so each visible query refetches every 20s (`refetchIntervalInBackground: false`, `refetchOnWindowFocus: true`). The teacher realtime channel (`lib/realtime/teacherChannel.ts`, mounted in `app/teacher/layout.tsx`) invalidates instantly on notifications **and** on direct `Referral` / `Intervention` / `CounselingSession` / `RiskSnapshot` table events (RLS scopes them to the adviser's own section and the filer's own referrals; `CounselingSession` invalidates both `interventions` and `referrals` because a booked session rewrites the referral's status/timeline; `RiskSnapshot` maps to the narrow `risk` scope so a snapshot can't churn ADM/SF10 queries). The poll is the safety net for writes that emit neither; note that a learner becoming risk-flagged with **no plan** emits no notification, so that card relies on the `RiskSnapshot` subscription + poll. Shared hooks the teacher shell renders (NotificationsBell, settings profile/data-sharing) poll too — do not add a bare `useQuery`/`queryClient.prefetchQuery` panel to a teacher page.
- Design rules live in `.kilo/skills/zentra-design/` (rounded-md, 1px borders, one accent, micro-motion 120–180ms). Every button renders at **32px height** — enforced globally in `frontend/src/app/globals.css` for `[data-slot="button"]` and native `<button>` with a Tailwind `h-6`–`h-10`, so don't hand-pick smaller/larger button heights (grid/calendar/heatmap cells are the exception and size themselves).
- Typography: the whole app (all role shells) renders in **Inter** (sans) — `--font-sans`/`--font-heading`/`--font-mono` all resolve to `var(--font-inter)` (loaded in `frontend/src/app/layout.tsx`, forced by `FontProvider` in `components/providers.tsx`). Never point a stylesheet at `--font-geist-mono` (removed — the old Geist Mono variable was renamed to `--font-inter`). **Minimum type size is 12px** (`0.75rem`) in every role shell — CSS `font-size`, inline recharts `fontSize`/ticks, and Tailwind `text-[…]` alike. Print-only A4 record sheets under `app/(print)` are the sole exception.
- Shared desk UI: `components/ui/kanban-board.tsx`, `kanban-overlay.tsx` (modal shell) and `pill.tsx` (status/metadata chips) are the standard; role wrappers (`PrincipalEmptyCard`, `GuidanceEmptyCard`, `*PageHeader`) alias `components/shared/*`. Desk-level empty states use `components/shared/page-empty-callout.tsx` (`PageEmptyCallout`) — the shared amber `InsightCallout` centered in the content area (one message per page, never inside a data table/board; filtered/search no-match notes stay inline). Status chip colours come from `lib/labels/status-tone.ts` — add new statuses there, never inline a `Badge` variant map. Sidebar nav icons come from `components/nav/sidebar-icons.ts` (`NAV_ICONS`) — never import a lucide icon directly for a nav item. **Every desk renders the same floating glass dock** (`components/nav/GlassDock.tsx`, fed by that desk's `*-sidebar.tsx` NAV + nav-count dots; no left rail or mobile tab bar any more) and its shell clears it with `.shellWithDock` (`padding-left: 5rem`, `4.25rem` under 768px, `margin-top: 3rem`). **Every in-page teacher search field is `<TeacherSearchField>` (`app/teacher/components/TeacherSearchField.tsx`)** — one 32px shell (single 1px border, amber `--amber-500` focus edge + soft amber glow, never the gray `--ring`), with icon, clear (X), Esc-to-clear and an optional `loading` spinner for debounced server searches; "nothing matched" copy comes from its `searchEmptyMessage(query, subject, hint?)` export (`No <subject> match “q”. <hint>`), so never hand-roll a search input or a one-off no-results message in the teacher shell. The topbar `TeacherGlobalSearch` palette is separate (⌘K trigger). Both registry overviews (`/record-keeper/overview`, `/registrar/overview`) render the same shared widgets from `components/registry/overview/` (`RegistryAttentionDeck`, `RegistryGradePanel`, `RegistryRequestsPanel`, `RegistryRecordsLedger`, `registryOverviewQuery`); every widget takes a `desk: "record-keeper" | "registrar"` prop that only swaps the query key/fetcher and the `/record-keeper/*` vs `/registrar/*` links — never fork the markup per desk.

## 7. KEY MODULES

Backend (paths relative to `backend/src/`):
- `modules/auth/*` — register (student/parent/staff), login/refresh/logout (argon2id + JWT + refresh cookie); the pending queue itself (list/LRN match/approve/reject via `approval.service.ts`) is served by `modules/admin/admin.routes.ts` now. - `modules/attendance/*` + `services/attendance*.ts` — bulk AM/PM and per-subject taking (PH/weekend/future guards), rate service, heatmaps, legacy tables.
- `modules/anecdotal/*` — records, folders, signatures, OCForm‑01 Excel workbook (`ocform01.workbook.ts`; assets copied on build). A learner may hold only **one live referral per type** (`referredToRole`): `referRecord` and `reopenReferral` reject a duplicate with `409 REFERRAL_ALREADY_OPEN` while any same-learner same-type referral is `pending`/`in_progress`/`escalated`/`info_requested`/`follow_up` (only `resolved`/`dismissed` free the slot; not term-scoped).
- `modules/interventions/*` — queue + case sessions, approvals, outcomes (auto-created by risk engine). Every write route must invalidate with `invalidateInterventionCaches()` (`interventions.repository.ts`), never a bare `invalidateTags(INTERVENTION_WRITE_TAGS)`: the guidance boards read the live risk cohort, which memoizes its whole scan — sessions + attachment counts included — for ~20s in `liveCohortCache` (`modules/risk/interventions.service.ts`) and is only re-keyed by `bumpRiskCohortVersion()`, so a booking/reschedule/completion/cancel/attachment write would otherwise serve the pre-write plan until the memo expired.
- `modules/adm/*` — profiles/meetings/invitees/attachments/devices/meta; ADM stage machine + eligibility + principal approve. `monitoring.routes.ts` serves the adviser ADM monitoring desk (`GET /api/adm/my-cases/:caseId`, module create/patch) — module upload links live on `AdmModule.submissionUrl` (saving one auto-marks the module submitted); access is resolved through `Section.adviserId`, and `/api/adm/my-cases` lists every ADM case in the adviser's section (any filer) for the **whole selected school year** (each case carries its `termNumber`), and a case from an earlier term still opens/edits from a later term's board. The case desk's module board **merges** that case's `AdmModule` rows with the section's `kind: adm` `AdvisoryModule` rows (read-only, per-learner status from `AdvisoryModuleSubmission`; edited on `/teacher/advisory/modules`) and computes progress over both.
- `modules/sf10/*` — records + lifecycle (verify→validate→release), append-only versions, desk banding, storage. **An SF10 record is LRN-keyed storage, not a learner relation**: `Sf10Record` carries `lrn` (+ `learnerName`, nullable `gradeLevel` read off the file) with `@@unique([lrn, desk])` and no profile FK — migration `20261117090000_sf10_lrn_keyed` backfilled legacy rows from the old `studentId`, deleted rows with no readable LRN, and dropped the column. `POST /api/sf10/upload-auto` (`uploadAuto` in `services/sf10/records.service.ts`) stores any file whose LRN it can read — including a learner the school has never enrolled (`matched.kind: "no-account"`) — and never creates a `User`/`StudentProfile`/`StudentRoster` or rewrites learner info; no LRN → `409 NEEDS_LRN`, and `studentCreated` is always false.
